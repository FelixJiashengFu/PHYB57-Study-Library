INTERPOLATION¶

Interpolation is the process of estimating unknown values of a function that fall within the range of known discrete data points.

Given a dataset of $n$ independent coordinates $x_i$ and corresponding dependent values $y_i$: $$(x_1, y_1), (x_2, y_2), \dots, (x_n, y_n)$$

The goal is to find an estimation function $\hat{f}(x)$ such that: $$\hat{f}(x_i) = y_i \quad \text{for every point in the dataset}$$

Interpolation is different from regression because it ensures the function passes through every data point. Regression assumes an underlying parameterized model (such as a straight line $y = mx + b$) and minimizes the overall discrepancy (residuals), meaning the fitted line rarely passes through all data points.

Interpolation is suitable when data points are highly reliable, low-noise measurements representing a continuous physical phenomenon (e.g. tracking vehicle trajectory over time).

LINEAR INTERPOLATION¶

The simplest approach is linear interpolation, which assumes that any intermediate point lies on the straight line segment connecting the two nearest known data points on either side.

For any $x$ lying in the interval $x_i \le x \le x_{i+1}$, the equation of the line connecting the two points is: $$\hat{f}(x) = y_i + \frac{y_{i+1} - y_i}{x_{i+1} - x_i}(x - x_i)$$

CUBIC SPLINE INTERPOLATION¶

A major limitation of linear interpolation is that the resulting curve has sharp, non-differentiable corners at each data point ($C^0$ continuity only). In physics and engineering, mechanical motion requires continuous velocities and continuous accelerations.

Cubic spline interpolation constructs a smooth curve through points using piecewise cubic polynomials: $$S_i(x) = a_i x^3 + b_i x^2 + c_i x + d_i \quad \text{for } x \in [x_i, x_{i+1}]$$

For $n$ data points, there are $n-1$ intervals, requiring $4(n-1)$ unknown coefficients. These are determined uniquely by enforcing:

  1. each spline passes through the given data points,
  2. the first and second derivatives are continuous at every data point,
  3. boundary conditions (default is to set second derivatives are outer endpoints to 0, but can be modified for SciPy's CubicSpline function).

LAGRANGE & NEWTON'S POLYNOMIAL INTERPOLATION¶

Instead of piecewise polynomials, we can find a single global polynomial of degree $n-1$ that passes through all $n$ data points.

Lagrange Polynomial Interpolation¶

The Lagrange polynomial expresses $L(x)$ as a linear combination of basis polynomials $P_i(x)$: $$L(x) = \sum_{i=1}^n y_i P_i(x)$$ where each basis polynomial $P_i(x)$ is defined as: $$P_i(x) = \prod_{j=1, j \ne i}^n \frac{x - x_j}{x_i - x_j}$$

Each basis polynomial has the property: $$P_i(x_j) = \begin{cases} 1 & \text{if } i = j \\ 0 & \text{if } i \ne j \end{cases}$$

Newton's Polynomial & Divided Differences¶

While mathematically identical to Lagrange's polynomial, Newton's representation is far more computationally efficient because adding a new data point does not require recalculating the existing polynomial coefficients.

The Newton polynomial of order $n-1$ is written: $$f(x) = a_0 + a_1(x - x_0) + a_2(x - x_0)(x - x_1) + \dots + a_n(x - x_0)(x - x_1)\cdots(x - x_{n-1})$$

The coefficients $a_i$ are calculated using the divided differences table: $$f[x_0, x_1] = \frac{f(x_1) - f(x_0)}{x_1 - x_0}, \qquad f[x_0, x_1, x_2] = \frac{f[x_1, x_2] - f[x_0, x_1]}{x_2 - x_0}$$

# function to calculate divided differences
def divided_diff(x, y):
    """
    Calculates the divided differences table for coordinate vectors x and y.
    Returns the full table matrix where the first row contains coefficients a_i.
    """
    n = len(y)
    coef = np.zeros([n, n])
    coef[:, 0] = y  # First column is y
    
    for j in range(1, n):
        for i in range(n - j):
            coef[i][j] = (coef[i + 1][j - 1] - coef[i][j - 1]) / (x[i + j] - x[i])
            
    return coef

def newton_poly(coef, x_data, x):
    """
    Evaluates the Newton polynomial at given point.
    """
    n = len(x_data) - 1
    p = coef[n]
    for k in range(1, n + 1):
        p = coef[n - k] + (x - x_data[n - k]) * p
    return p

a_s = table[0, :]

plt.figure(figsize=(7, 4.2))

ROOT FINDING¶

A root (or zero) of a function $f(x)$ is any value $x_r$ such that: $$f(x_r) = 0$$

While simple algebraic equations (like $x^2 - 9 = 0 \implies x = \pm 3$) can be solved analytically, transcendental functions like $f(x) = \cos(x) - x$ have no closed-form algebraic solution and require numerical iterative methods.

Because digital computers use finite floating-point arithmetic, an algorithm almost never lands exactly on $f(x) = 0.000000000\dots$ Instead, an iterative method terminates when the error is smaller than a specified tolerance (tol).

Two common error metrics are used:

  1. Function residual: $|f(x_k)| < \text{tol}$ (measures how close the output is to zero).
  2. Step size: $|x_{k+1} - x_k| < \text{tol}$ (measures when successive guesses stop changing).

An inbuilt function for root finding is SciPy's fsolve. It accepts the function and an initial guess for the root as parameters; you can also specify the tolerance and the maximum number of iterations, but the default values are $1.49012^{-08}$ and $400$ respectively. fsolve can also be used for a system of equations; simply pass arrays of functions and initial guesses. Additionally, you can pass an array of initial guesses for just one function to find multiple roots.

THE BISECTION METHOD¶

The bisection method of root finding is a bracketing method based on the Intermediate Value Theorem: if $f(x)$ is continuous on an interval $[a, b]$ and $f(a) \cdot f(b) < 0$ (opposite signs), then there must exist at least one root $c \in [a, b]$ such that $f(c) = 0$.

The bisection method algorithm:

  1. Check that $f(a)$ and $f(b)$ have opposite signs ($f(a) \cdot f(b) < 0$).
  2. Compute the midpoint: $m = \frac{a + b}{2}$.
  3. If $|f(m)| < \text{tol}$, $m$ is the accepted root.
  4. If $\text{sign}(f(a)) == \text{sign}(f(m))$, the root lies in $[m, b]$; update $a \leftarrow m$. Otherwise, the root lies in $[a, m]$; update $b \leftarrow m$.
  5. Repeat until interval length or residual is below tolerance.

The bisection method is very reliable: it is guaranteed to converge if initial signs differ. However, it converges linearly, so it can be slower compared to other methods.

In [6]:
# function to implement the bisection method
def my_bisection(f, a, b, tol):
    """
    Approximates a root of f bounded by a and b to within tolerance tol.
    """
    # raise exception if signs at interval ends are not different
    if np.sign(f(a)) == np.sign(f(b)):
        raise ValueError(f"The scalars a={a} and b={b} do not bound a root (same sign).")
    
    steps = 0
    while True:
        steps += 1
        m = (a + b) / 2.0     # find midpoint of current interval
        
        if abs(f(m)) < tol or (b - a) / 2.0 < tol:
            return m, steps   # return root if within tolerance
        
        if np.sign(f(a)) == np.sign(f(m)):
            a = m             # update boundary a if sign of midpoint matches
        else:
            b = m             # else update boundary b

# example from slides
f_sqrt2 = lambda x: x**2 - 2

for tol_val in [0.1, 0.01, 1e-6]:
    root_val, iterations = my_bisection(f_sqrt2, 0, 2, tol_val)
    print(f"Tolerance = {tol_val:7g} -> Root = {root_val:10.8f} in {iterations:2d} iterations (Exact: {np.sqrt(2):.8f})")

NEWTON-RAPHSON METHOD & MULTIPLE ROOTS¶

The Newton-Raphson method is an iterative method that uses the local tangent line (first-order Taylor series approximation) to project the next guess: $$f(x) \approx f(x_0) + f'(x_0)(x_1 - x_0) = 0$$

Solving for $x_1$ yields the Newton step: $$x_{k+1} = x_k - \frac{f(x_k)}{f'(x_k)}$$

Near a root, Newton-Raphson exhibits quadratic convergence (the number of accurate decimal places roughly doubles with each iteration!) which makes it more efficient than the bisection method. However, it is very sensitive to the initial guess (may oscillate or diverge if too far from the root or converge to a different root), and can blow up/fail if $f'(x)$ approaches 0.

# Newton-Raphson Method vs. SciPy fsolve
def my_newton(f, df, x0, tol, max_iter=100):
    """
    Iterative Newton-Raphson method for root finding.
    """
    x = x0
    for i in range(1, max_iter + 1):
        fx = f(x)    # evaluate function value at x
        if abs(fx) < tol:
            return x, i
        dfx = df(x)  # evaluate derivative value at x
        if abs(dfx) < 1e-12:
            raise ZeroDivisionError("Derivative near zero. Method failed.")
        x = x - fx / dfx
    return x, max_iter

# test on f(x) = x^2 - 2
f = lambda x: x**2 - 2
df = lambda x: 2 * x

r_newton, iters = my_newton(f, df, x0=1.5, tol=1e-6)
print(f"Newton-Raphson Root: {r_newton:.12f} in only {iters} iterations!")
print(f"Bisection required 21 iterations for the same 1e-6 precision.\n")

NUMERICAL DIFFERENTIATION¶

THE NUMERICAL GRID & FINITE DIFFERENCE FORMULATIONS¶

In computational science, continuous functions are frequently represented on a numerical grid—a discrete set of evenly spaced points over a domain: $$x_j = x_0 + j \cdot h, \quad j = 0, 1, 2, \dots, N$$ where $h$ is the uniform step size (grid spacing).

The fundamental definition of the derivative from calculus is: $$f'(x) = \lim_{h \to 0} \frac{f(x + h) - f(x)}{h}$$

On a discrete grid where $h$ cannot be taken to the infinitesimal limit, we use finite difference approximations based on neighboring grid values:

  1. Forward Difference: estimating the slope at a point $x_j$ as the slope between $x_j$ and $x_{j+1}$ $$f'(x_j) \approx \frac{f(x_{j+1}) - f(x_j)}{h}$$
  2. Backward Difference: estimating the slope at a point $x_j$ as the slope between $x_{j-1}$ and $x_j$ $$f'(x_j) \approx \frac{f(x_j) - f(x_{j-1})}{h}$$
  3. Central Difference: estimating the slope at a point $x_j$ as the slope between $x_{j-1}$ and $x_{j+1}$ $$f'(x_j) \approx \frac{f(x_{j+1}) - f(x_{j-1})}{2h}$$

Taylor Series Derivation & Accuracy¶

To understand why central difference is superior, we can derive the error terms using Taylor series expansions around $x_j$:

$$f(x_j + h) = f(x_j) + h f'(x_j) + \frac{h^2}{2!} f''(x_j) + \frac{h^3}{3!} f'''(x_j) + \mathcal{O}(h^4) \quad \text{--- (Eq. 1)}$$ $$f(x_j - h) = f(x_j) - h f'(x_j) + \frac{h^2}{2!} f''(x_j) - \frac{h^3}{3!} f'''(x_j) + \mathcal{O}(h^4) \quad \text{--- (Eq. 2)}$$

Forward Difference Accuracy:¶

Rearranging Eq. 1 for $f'(x_j)$: $$f'(x_j) = \frac{f(x_j + h) - f(x_j)}{h} - \frac{h}{2} f''(x_j) - \dots = \frac{f(x_{j+1}) - f(x_j)}{h} + \mathcal{O}(h)$$

  • The leading truncation error is proportional to $h$.
  • First-order accurate $\mathcal{O}(h)$: halving $h$ reduces the error by a factor of 2.

We get the same stucture for Backward Difference.

Central Difference Accuracy:¶

Subtracting Eq. 2 from Eq. 1: $$f(x_j + h) - f(x_j - h) = 2h f'(x_j) + \frac{2h^3}{6} f'''(x_j) + \mathcal{O}(h^5)$$ Dividing by $2h$: $$f'(x_j) = \frac{f(x_{j+1}) - f(x_{j-1})}{2h} - \frac{h^2}{6} f'''(x_j) - \dots = \frac{f(x_{j+1}) - f(x_{j-1})}{2h} + \mathcal{O}(h^2)$$

  • Second-order accurate $\mathcal{O}(h^2)$: halving $h$ reduces the error by a factor of 4.

# comparing forward and central differences
h = 0.1
x_grid = np.arange(0, 2 * np.pi, h)
y_grid = np.cos(x_grid)

# forward difference: dy/dx approx (y[j+1] - y[j]) / h
forward_diff = np.diff(y_grid) / h       # np.diff finds differences between consecutive elements in an array
x_fwd = x_grid[:-1]

# backward difference: dy/dx approx (y[j] - y[j-1]) / h
backward_diff = np.diff(y_grid) / h
x_bwd = x_grid[1:]

x_cent = x_grid[1:-1]

exact_bwd = -np.sin(x_bwd)
exact_cent = -np.sin(x_cent)

err_bwd = np.max(np.abs(exact_bwd - backward_diff))

ERROR SCALING¶

To verify the theoretical orders of accuracy $\mathcal{O}(h)$ and $\mathcal{O}(h^2)$, we study how the maximum absolute error scales as we systematically decrease $h$ across several orders of magnitude: $$h = 2^{-1}, 2^{-2}, \dots, 2^{-18}$$

On a log-log plot: $$\log(\text{Error}) \approx \log(C \cdot h^p) = p \log(h) + \log(C)$$

  • The slope of the line reveals the convergence order $p$:
    • Forward difference: slope = 1
    • Central difference: slope = 2
In [9]:
# log-log error analysis over diminishing step sizes h
iterations = 10
h_val = 1.0

step_sizes = []
errors_fwd = []
errors_cent = []

for i in range(iterations):
    h_val /= 2.0
    step_sizes.append(h_val)

    y = np.cos(x)
    
    # forward difference
    fwd = np.diff(y) / h_val

APPROXIMATING HIGHER-ORDER DERIVATIVES¶

Higher-order derivatives (such as second derivatives $f''(x)$) are fundamental in physics and engineering. We can derive a numerical differentiation approximation using Taylor series again.

Adding the forward and backward expansions (Eq. 1 and Eq. 2): $$f(x_j + h) + f(x_j - h) = 2f(x_j) + h^2 f''(x_j) + \frac{h^4}{12} f^{(4)}(x_j) + \mathcal{O}(h^6)$$

Rearranging for the second derivative $f''(x_j)$: $$f''(x_j) = \frac{f(x_{j+1}) - 2f(x_j) + f(x_{j-1})}{h^2} + \mathcal{O}(h^2)$$

This is the standard second-order central difference formula for the second derivative, requiring three points $(x_{j-1}, x_j, x_{j+1})$ with truncation error $\mathcal{O}(h^2)$.

SENSITIVITY TO NOISE¶

Real-world data from sensors, accelerometers, or optical encoders always contains measurement noise.

Consider a clean signal $f(x) = \cos(x)$ contaminated by high-frequency noise: $$f_{\epsilon, \omega}(x) = \cos(x) + \epsilon \sin(\omega x)$$ where:

  • $\epsilon = 0.01$ is a small noise amplitude (only 1% of the signal).
  • $\omega = 100$ is a high angular frequency.

Taking the analytical derivative: $$f'_{\epsilon, \omega}(x) = -\sin(x) + \epsilon \cdot \omega \cos(\omega x)$$

Look at the noise amplitude in the derivative: $$\epsilon \cdot \omega = 0.01 \times 100 = 1.0$$

Even though the noise was barely 1% in the original data (completely invisible to the naked eye), the derivative's noise amplitude is 1.0—equal in magnitude to the actual signal.

In finite differences, the issue is even worse: $$\frac{\Delta y_{\text{noise}}}{h}$$ As step size $h$ becomes smaller, dividing by $h$ amplifies any random noise $\Delta y$. Differentiation amplifies noise, and we should be wary of this limitation.

NUMERICAL INTEGRATION¶

Numerical integration approximates the definite integral: $$I = \int_a^b f(x)\, dx$$

Geometrically, the integral represents the signed area between the curve and the x-axis.

Left and Right Riemann Sums:¶

We divide the domain $[a, b]$ into $n-1$ subintervals of equal width: $$h = \frac{b - a}{n - 1}$$

  • Left Riemann Sum: Rectangles calculated using the function value at the left boundary of each subinterval: $$\int_a^b f(x)\, dx \approx \sum_{i=0}^{n-2} h \cdot f(x_i)$$
  • Right Riemann Sum: Rectangles calculated using the function value at the right boundary: $$\int_a^b f(x)\, dx \approx \sum_{i=1}^{n-1} h \cdot f(x_i)$$

Single-interval error is of order $\mathcal{O}(h^2)$. Global error across all $N = (b-a)/h$ intervals is of the order $\mathcal{O}(h)$, so finer subintervals are crucial for increased accuracy.

MIDPOINT RULE¶

The midpoint rule significantly improves upon Riemann sums by evaluating the function at the midpoint of each subinterval to calculate the area of the rectangles: $$y_i = \frac{x_i + x_{i+1}}{2}$$ $$\int_a^b f(x)\, dx \approx \sum_{i=0}^{n-2} h \cdot f(y_i)$$

It is second-order accurate because the symmetry helps cancel out lower-order error terms in the Taylor expansion. However, this method only works if the data at midpoints is available to you.

In [12]:
# left/right Riemann sums vs midpoint rule
# integral of sin(x) from 0 to pi with n = 11 points (exact value = 2.0)
a = 0
b = np.pi
n = 11
h = (b - a) / (n - 1)
x = np.linspace(a, b, n)
f = np.sin(x)

# left Riemann sum
I_riemannL = h * np.sum(f[:-1])
err_riemannL = 2.0 - I_riemannL

# right Riemann sum
I_riemannR = h * np.sum(f[1:])
err_riemannR = 2.0 - I_riemannR

# midpoint rule
x_midpoints = (x[:-1] + x[1:]) / 2.0
I_mid = h * np.sum(np.sin(x_midpoints))
err_mid = 2.0 - I_mid

print(f"Grid points n = {n}, Step size h = {h:.4f}")
print(f"Left Riemann Integral:  {I_riemannL:.8f} | Error: {err_riemannL:.8f}")
print(f"Right Riemann Integral: {I_riemannR:.8f} | Error: {err_riemannR:.8f}")
print(f"Midpoint Rule Integral: {I_mid:.8f} | Error: {err_mid:.8f}")
print(f"Midpoint error is ~{abs(err_riemannL / err_mid):.1f}x smaller than Riemann.")

THE TRAPEZOID RULE¶

The trapezoid rule models the function on each subinterval as a straight line (linear interpolation between endpoints). Instead of calculating the area of a rectangle, we calculate the area of the trapezoid formed by this linear interpolation for each subinterval.

The area of a single trapezoid on $[x_i, x_{i+1}]$ is: $$\text{Area}_i = \frac{h}{2} \left[ f(x_i) + f(x_{i+1}) \right]$$

Summing over all subintervals gives the trapezoid rule: $$\int_a^b f(x)\, dx \approx \sum_{i=0}^{n-2} \frac{h}{2}\left[ f(x_i) + f(x_{i+1}) \right]$$

We can optimise the calculation. Notice that every interior point $x_1, x_2, \dots, x_{n-2}$ is shared by two adjacent trapezoids and therefore counted twice, whereas the endpoints $x_0$ and $x_{n-1}$ are counted only once: $$\int_a^b f(x)\, dx \approx \frac{h}{2} \left[ f(x_0) + 2 \sum_{i=1}^{n-2} f(x_i) + f(x_{n-1}) \right]$$

The trapezoid rule is second-order accurate like the midpoint rule, but uses only the given grid points, making it directly applicable to experimental tabulated data where midpoints cannot be measured. However, it is less accurate for functions with higher curvature where a linear interpolation between points is not a good approximation.

In [13]:
# trapezoid rule implementation for sin(x) from 0 to pi
I_trap = (h / 2.0) * (f[0] + 2 * np.sum(f[1:-1]) + f[-1])
err_trap = 2.0 - I_trap

print(f"Trapezoid Rule Integral: {I_trap:.8f}")
print(f"Trapezoid Rule Error:    {err_trap:.8f}")

SIMPSON'S 1/3 RULE (QUADRATIC INTERPOLATION)¶

Instead of approximating $f(x)$ with straight line segments, Simpson's rule fits a quadratic polynomial (parabola) through sets of three consecutive points across two adjacent subintervals $[x_{i-1}, x_{i+1}]$ (width $2h$). Then it integrates the parabolic functions exactly over each subinterval.

Summing over all pairs of intervals yields Simpson's rule: $$\int_a^b f(x)\, dx \approx \frac{h}{3} \left[ f(x_0) + 4 \sum_{i \text{ odd}} f(x_i) + 2 \sum_{i \text{ even}} f(x_i) + f(x_{n-1}) \right]$$

Simpson's rule requires an odd number of grid points $n$ (so that the number of subintervals $n-1$ is even). It is fourth-order accurate $\mathcal{O}(h^4)$ because the cubic term cancels out symmetrically in the Taylor expansion. Simpson's rule is therefore exact for all polynomials up to degree 3.

In [14]:

err_simp = 2.0 - I_simp

print(f"Simpson's Rule Integral: {I_simp:.10f}")
print(f"Simpson's Rule Error:    {err_simp:.10f}")

SCIPY INTEGRATION TOOLS (scipy.integrate)¶

In Python, scipy.integrate provides optimised functions for both discrete data arrays and analytical functions:

  1. trapezoid: computes the total trapezoidal integral for given discrete arrays $y$ and $x$ (arguments)
  2. cumulative_trapezoid: computes the running cumulative integral, same arguments as trapezoid: $$F(X) = \int_{x_0}^X f(t)\, dt$$
  3. quad: higher accuracy method, returning both the estimated integral and an upper bound on absolute numerical error; takes function and boundary values as arguments
